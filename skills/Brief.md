# Product Brief｜My Workspace

**产品名称：** My Workspace  
**产品定位：** Personal Life & Research Management System  
**产品类型：** 个人 桌面端工作台  
**版本：** V1.0  
**开发目标：** 构建一个集研究管理、日常学习、习惯追踪、健康管理和生活事务管理于一体的个人数字工作台。

---

# 1. 产品概述（Product Overview）

## 1.1 产品愿景

打造一个具有 macOS 桌面体验的个人数字工作台，让用户能够在一个统一的空间中管理自己的学术研究、学习计划、日常习惯、健康数据和生活事务。

产品希望通过文件夹式交互、日历可视化、文档阅读、AI Agent 等方式，让个人信息管理更加直观、优雅和高效。

## 1.2 产品核心模块

产品由三个一级模块组成：

1. 论文阅读（Research）
    
2. 日常活动（Daily Activities）
    
3. 事件记录（Life Management）
    

具体功能：

### A. 论文阅读

- 最新论文
    
- 论文阅读
    

### B. 日常活动

- 多邻国打卡
    
- 不背单词打卡
    
- 减肥打卡
    
- 网课学习
    

### C. 事件记录

- 备忘录
    
- 提醒事项
    

---

# 2. 产品整体设计（Overall Design）

## 2.1 核心交互形式

产品整体采用立式文件夹（Vertical Folder Workspace）的视觉设计。

用户打开 App 后，首先看到一个具有真实文件夹收纳感的桌面工作区。

交互要求：

1. 一级模块以立着排列的文件夹形式展示。
    
2. 鼠标悬停在文件夹上时，文件夹以抽取、展开的动画形式展示其下属功能。
    
3. 用户点击子功能后，进入对应的具体页面。
    
4. 页面左侧始终保留固定导航栏，允许用户直接切换不同模块。
    
5. 页面切换时应保持合理的过渡动画，避免突兀的跳转。
    
6. 文件夹视觉效果应具有层次感、空间感和轻微的纵深效果。
    

## 2.2 全局导航

左侧导航栏采用树状层级结构：

Research

- 最新论文
    
- 论文阅读
    

Daily Activities

- 多邻国打卡
    
- 不背单词打卡
    
- 减肥打卡
    
- 网课学习
    

Life Management

- 备忘录
    
- 提醒事项
    

导航要求：

- 一级模块可展开或收起。
    
- 二级页面可以直接点击进入。
    
- 当前页面具有清晰的选中状态。
    
- 支持导航栏收缩和展开。
    
- 页面切换后保留合理的历史状态。
    

## 2.3 视觉风格

整体参考 macOS 的设计语言。

核心关键词：

- Glassmorphism（毛玻璃）
    
- Minimalism（极简）
    
- Soft Shadow（柔和阴影）
    
- Translucent Layers（透明层次）
    
- Smooth Animation（流畅动画）
    
- Desktop Experience（桌面体验）
    

支持两种主题：

**Light Mode：** 白天模式，采用明亮背景、半透明白色卡片和柔和阴影。

**Night Mode：** 夜览模式，采用深色背景、半透明深色面板和低亮度强调色。

## 2.4 颜色规范

Primary: #18181b  
Secondary: #fafafa  
Accent 1: #3b82f6  
Accent 2: #8b5cf6  
Accent 3: #ec4899  
Accent 4: #f97316

颜色使用原则：

- Primary 用于主要文字和重要视觉元素。
    
- Secondary 用于基础背景及明亮表面。
    
- Blue 用于主要操作、链接和选中状态。
    
- Purple 用于 AI 相关功能及辅助强调。
    
- Pink 用于习惯、成就和状态提示。
    
- Orange 用于提醒、待办和重要事项。
    

夜览模式需要提供对应的深色配色映射，不能简单地反转所有颜色。

# 3. 功能需求（Functional Requirements）

# Module A：论文阅读（Research）

## A1. 最新论文（Latest Papers）

### 产品目标

帮助用户快速发现信息系统工程领域的新论文，了解学术领域的发展趋势，并通过 AI Agent 辅助进行文献检索和研究探索。

### 页面布局

采用左右分栏布局：

左侧：论文发现与展示区。

右侧：AI Agent 对话区。

### 默认展示内容

首次进入页面时，左侧自动展示信息系统工程领域近两年的较新且引用较多的期刊和学术文献。

展示数量：

- 国外文献：5 篇
    
- 国内文献：3 篇
    

文献来源：

- 国内外学术期刊
    
- 学术论文数据库
    
- 其他可靠的学术资源
    

论文展示形式采用书籍或文献卡片形式。

每篇论文需要展示：

- 论文标题
    
- 作者
    
- 发表年份
    
- 期刊名称
    
- 摘要
    
- 引用次数（如有可靠数据）
    
- DOI 或原文链接
    
- 论文来源
    
- 论文语言
    

### 研究趋势总结

在论文列表上方或独立区域展示一段领域研究趋势总结。

总结内容：

1. 当前信息系统工程领域的主要研究方向。
    
2. 近两年受到关注的新兴主题。
    
3. 当前研究热点。
    
4. 可能的发展趋势。
    
5. 值得进一步探索的研究问题。
    

总结必须基于真实检索到的论文和来源，不得编造引用次数或论文信息。

### AI Agent 对话区

连接智谱 AI API。

主要能力：

- 用户输入关键词。
    
- Agent 根据关键词检索相关领域的最新论文。
    
- Agent 对论文进行筛选和整理。
    
- 将符合要求的论文展示在左侧论文列表。
    
- 支持用户继续追问和调整搜索范围。
    
- 可以对论文进行摘要、对比和初步分析。
    

示例：  
用户输入：  
"Large Language Models in Information Systems"

Agent 返回：

- 相关论文列表
    
- 论文发表时间
    
- 研究主题
    
- 主要研究结论
    
- 论文原文入口
    

注意：  
AI API Key 必须通过环境变量或安全密钥管理机制配置，不得直接写入前端代码或提交到 Git 仓库。

### 论文阅读入口

点击左侧某篇论文后，可以查看论文详情。

用户点击「开始阅读」：

- 将论文加入论文阅读模块。
    
- 默认归入「未读」文件夹。
    
- 可以跳转至论文阅读页面。
    
- 保留论文来源、DOI 和元数据。

## A2. 论文阅读（Paper Reader）

### 产品目标

为用户提供一个集文献管理、PDF 阅读、批注、高亮和阅读进度管理于一体的学术阅读空间。

### 页面布局

左侧：论文文件夹与文献列表。

右侧：论文阅读区域。

### 默认文件夹

1. 未读（Unread）
    
2. 最近阅读中（Currently Reading）
    
3. 已读完（Completed）
    

### 文献管理逻辑

未读：

- 存放尚未开始阅读的论文。
    
- 点击论文后展示阅读预览。
    
- 点击「开始阅读」后，将论文移动到「最近阅读中」。
    

最近阅读中：

- 存放正在阅读的论文。
    
- 支持继续上次阅读的位置。
    
- 支持高亮、批注和阅读进度记录。
    

已读完：

- 存放已经完成阅读的论文。
    
- 保留原始论文、批注和阅读记录。
    
- 支持重新打开阅读。
    

### 文献阅读功能

支持以下文件格式：

- PDF
    
- DOC / DOCX
    
- Markdown（MD）
    

支持用户上传本地文件或文档。

阅读器应提供：

- 页面缩放
    
- 翻页
    
- 全屏阅读
    
- 页面跳转
    
- 搜索文本
    
- 阅读进度记录
    
- 高亮标注
    
- 添加批注
    
- 查看已有批注
    
- 删除或修改批注
    

### 高亮和批注

用户可以选中文章中的文字并添加高亮。

高亮支持多种颜色。

用户可以为选中的文本添加批注。

批注需要关联：

- 对应文献
    
- 对应页面或段落
    
- 原文内容
    
- 批注内容
    
- 创建时间
    

### 保存逻辑

用户点击「保存」后：

1. 保存当前阅读进度。
    
2. 保存所有高亮和批注。
    
3. 提示保存成功。
    
4. 让用户选择文章状态：
    
    - 继续阅读：保留在最近阅读中。
        
    - 已读完：移动至已读完文件夹。
        

保存后的内容应在重新打开文献时完整恢复。

# Module B：日常活动（Daily Activities）

## B1. 多邻国打卡（Duolingo Tracker）

### 产品目标

通过日历和连续打卡数据记录多邻国学习习惯。

### 页面设计

整体参考 Duolingo App 的视觉风格。

主要功能：

- 月历展示。
    
- 每日打卡状态。
    
- 连续打卡天数。
    
- 总打卡天数。
    
- 学习记录。
    
- 每日完成状态标记。
    

用户可以手动记录每日是否完成学习。

页面可以展示连续打卡统计和简单的学习趋势。

## B2. 不背单词打卡（Vocabulary Tracker）

### 产品目标

记录每日单词学习情况，并通过单词卡片辅助英语学习。

### 页面设计

与多邻国打卡模块保持相似的日历布局。

主要功能：

- 每日学习打卡。
    
- 连续学习天数。
    
- 总学习天数。
    
- 学习记录。
    
- 月历视图。
    
- 单词及短语卡片展示。
    

### 单词卡片

在日历旁边展示单词或短语卡片。

卡片内容：

- 英文单词或短语
    
- 中文释义
    
- 音标（如有）
    
- 示例句子
    

支持切换或刷新展示的单词。

## B3. 减肥打卡（Weight & Health Tracker）

### 产品目标

建立个人体重和健康数据记录系统，通过可视化方式帮助用户观察长期变化。

### 页面布局

采用数据仪表盘形式。

主要功能：

**1. 体重记录**

- 添加每日体重。
    
- 查看历史体重。
    
- 支持曲线图。
    
- 支持日历视图。
    
- 展示体重变化趋势。
    

**2. 喝水记录**

- 每日饮水量记录。
    
- 设置每日饮水目标。
    
- 展示目标完成进度。
    
- 支持多次饮水记录。
    

**3. BMI 测量**

- 输入身高和体重。
    
- 自动计算 BMI。
    
- 展示计算结果。
    
- 保存历史记录。
    

**4. 体脂率记录**

- 手动输入体脂率。
    
- 记录历史变化。
    
- 支持趋势曲线展示。
    

数据展示要求：

- 支持曲线图。
    
- 支持日历视图。
    
- 支持切换不同时间范围。
    
- 支持查看历史记录。
    

注意：BMI 和体脂率仅作为个人记录与趋势观察工具，不应将其作为医疗诊断依据。

## B4. 网课学习（Online Course Tracker）

### 产品目标

管理网课学习进度，并为不同课程建立对应的笔记和资料空间。

### 页面布局

采用课程文件夹与日历结合的形式。

### 主要功能

**1. 课程管理**

- 创建课程。
    
- 上传课程文件夹或文件。
    
- 展示课程列表。
    
- 记录课程学习进度。
    

**2. 文件管理**  
支持上传：

- PDF
    
- Word
    
- Markdown
    
- 图片
    
- 其他常见学习资料
    

**3. 笔记管理**

- 为每门课程建立独立笔记空间。
    
- 支持创建笔记。
    
- 支持编辑和保存。
    
- 支持 Markdown 格式。
    
- 支持关联课程资料。
    

**4. 学习日历**

- 每日学习打卡。
    
- 查看学习记录。
    
- 记录课程学习进度。
    

用户点击课程后，可以查看课程相关资料、学习记录和笔记。

# 4. 全局功能需求（Global Requirements）

## 4.1 主题切换

支持 Light Mode 和 Night Mode。

用户可以手动切换主题。

主题切换后，整个应用的页面、组件、文字、图标和交互状态需要保持一致。

## 4.2 数据持久化

用户创建、修改和上传的数据应当能够持久化保存。

包括：

- 论文及其元数据。
    
- 论文阅读进度。
    
- 高亮与批注。
    
- 日常打卡。
    
- 体重和饮水记录。
    
- 课程资料和笔记。
    
- 备忘录。
    
- 提醒事项。
    

页面刷新或重新打开应用后，数据不能无故丢失。

## 4.3 响应式布局

优先适配桌面端，尤其是 macOS 环境。

同时考虑平板和移动端的基础适配。

## 4.4 文件管理

支持本地文件上传、文件解析和内容展示。

需要处理文件格式不支持、文件过大、解析失败等异常情况。

## 4.5 数据安全

- 妥善管理 API Key。
    
- 保护个人文件和数据。
    
- 防止未经授权的数据访问。
    
- 对删除操作提供确认。
    
- 对重要数据提供备份或导出能力。

# 5. 用户核心使用流程（User Journey）

## 场景一：阅读一篇最新论文

1. 用户打开工作台。
    
2. 进入「最新论文」。
    
3. 浏览系统推荐的国内外论文。
    
4. 通过右侧 AI Agent 搜索感兴趣的研究方向。
    
5. 点击某篇论文。
    
6. 点击开始阅读。
    
7. 系统将论文加入「未读」文件夹并打开阅读界面。
    
8. 用户开始阅读并进行高亮、批注。
    
9. 用户点击保存。
    
10. 选择继续阅读或标记为已读完。
    

## 场景二：记录每日学习

1. 用户进入「日常活动」。
    
2. 选择多邻国或不背单词。
    
3. 在日历中完成当日打卡。
    
4. 系统更新连续打卡天数。
    
5. 用户查看自己的学习记录。
    

## 场景三：记录健康数据

1. 用户进入减肥打卡。
    
2. 输入当天体重。
    
3. 记录饮水量。
    
4. 查看 BMI 和体脂率。
    
5. 查看历史曲线。
    
6. 通过日历回顾每日记录。
    

## 场景四：学习网课

1. 用户进入网课学习。
    
2. 创建一门课程。
    
3. 上传课程资料。
    
4. 创建学习笔记。
    
5. 记录当天学习情况。
    
6. 下次进入课程时继续学习。

# 7. 非功能性需求（Non-functional Requirements）

1. 视觉风格统一，避免不同模块像独立拼接的网站。
    
2. 页面交互流畅，避免不必要的加载和动画卡顿。
    
3. 数据必须可靠持久化。
    
4. 文件上传和解析必须有明确的状态反馈。
    
5. API 调用失败时提供合理错误提示。
    
6. 代码结构清晰，模块之间保持低耦合。
    
7. 支持后续增加新的功能模块。
    
8. 个人数据和 API 密钥需要安全保护。
    
9. 所有核心操作都应提供明确的成功或失败反馈。

# 8. 产品验收标准（Acceptance Criteria）

产品第一版交付时，需要满足：

1. 用户可以正常打开工作台。
    
2. 文件夹悬停可以展开子功能。
    
3. 点击导航可以正确切换页面。
    
4. 两种主题可以正常切换。
    
5. 各个一级和二级模块均可以进入。
    
6. 论文搜索可以正常调用配置的 AI 服务及检索来源。
    
7. 论文能够在不同阅读状态文件夹间切换。
    
8. PDF 可以正常打开和阅读。
    
9. 高亮和批注可以保存并恢复。
    
10. 日常打卡能够正确记录和统计。
    
11. 健康记录能够正确保存并展示图表。
    
12. 网课课程和笔记能够正常创建和管理。
    
13. 备忘录和提醒事项能够正常增删改查。
    
14. 刷新页面后，已有数据仍然存在。
    
15. 核心功能经过实际测试，不存在阻塞性问题。

# 9. 待确认事项（Open Questions）

以下内容暂时不作为已经确定的开发要求，需要在正式技术设计前进一步确认：

1. 是否需要用户登录？是否为纯个人使用？
    
2. 数据需要保存在本地，还是云端数据库？
    
3. 是否需要多设备同步？不需要
    
4. 论文检索具体使用哪些学术数据源？
    
5. 智谱 API 负责对话和分析，还是还需要独立的论文搜索服务？都需要
    
6. 是否需要 AI 对上传论文进行全文总结？
    
7. Word 文档是否必须支持原文排版和精确批注？
    
8. 是否需要提醒事项的系统通知？
    
9. 是否需要导出体重、学习和打卡数据？
    
10. 是否需要自动备份上传的论文和笔记？
    

**开发约束：** 对尚未确认的需求，Agent 应主动提出问题或给出推荐方案，不得自行将推测当作已确认的产品决策。
